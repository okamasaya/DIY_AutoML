# DIY AutoML

**機械学習のスコアに、誤差評価を添える。**

データを増やすべきか、集め方やラベルを見直すべきか。評価値とその揺れ、評価した条件を残し、次に何を調べるかを議論するために自作しているツールです。区間幅だけでデータ量不足や品質不良を判定する機能は、今後の課題です。

### 身近な公開データで、小さく検証

主要5モデルを学習側で選定し、保留した約20%を選んだ1モデルの評価に使用。各テーマ最大2,000行の試行です。

| 題材 | モデルのmacro F1 | 単純ルールのmacro F1 | モデルの条件付き95%区間 |
| --- | ---: | ---: | ---: |
| ホテルのキャンセル | 0.527 | 0.571 | 0.477〜0.576 |
| カフェ券の受取回答 | 0.692 | 0.652 | 0.647〜0.739 |
| 通販の再購入 | 0.624 | 0.613 | 0.573〜0.672 |

macro F1は各クラスのF1を同じ重みで平均した指標で、1が最大です。異なる題材の優劣を順位付けする点数ではありません。

ホテルでは単純ルールが上回り、通販の差は約0.011でした。カフェ券では「受け取る」と判定した205回答のうち66件が拒否回答で、受取回答の見逃しも57件ありました。**何件間違えたか、普段の判断と何が違うかまで確認します。** 方法間の差の有意性や施策の利益は未評価です。

### 確かめられる条件を残す

- **選定と評価を分離：** 学習側の共通5foldでモデルを選び、標準化も学習側だけで実施。testの成績で選び直しません。
- **評価値の揺れを計算：** 固定モデルの正解・予測をpaired bootstrapで再標本化。既定はクラス件数固定・1,000反復で、標準誤差とpercentile区間を計算します。ホテルF1の標準誤差は約0.0263でした。
- **結果を検査できる形で保存：** Excel・図に加え、予測・分割・設定を保存。DL/ULでは指定した初期化等の反復も扱います。

### 2つの利用者への入口

**DS向け：** 現在はGitHubから導入し、Python API・Notebook・CLIで実行できます。推定対象・分割・保存値を確認できる構成です。完成目標はPyPIで配布するPythonパッケージです。

**ビジネス向け：** 主要モデルと小規模な計算を中心に、件数・単純ルールとの比較・揺れ・注意点を読む入口を目指します。完成目標は、ファイルを渡してExcelを受け取る使いやすい廉価版アプリです。画面と提供方法・価格は今後です。

### 数字を使うときの前提

表の区間は学習済みモデルと観測クラス件数に条件付けた行単位の計算で、行の独立性・代表性の確認が必要です。カフェ券は同じ回答者の複数回答を含みIDがないため、この区間は参考値です。学習・選定からの変動、将来の変化、数値計算誤差や系統的な偏りを網羅しません。狭い区間だけで品質が良いとは判断できません。

**現在：** 数値・欠損なし・ラベル付きの分類CSVに対応。SL5モデル、UL54候補、TensorFlowの小規模MLPと誤差評価・Excel出力を実装しています。予測指標とクラスタ指標は分けて扱います。

**次へ：** データ点検・評価条件の記録 → 顧客や時間を考慮した評価 → 学習曲線・学習手続きの変動 → アプリ化。PyTorchは追加準備まで、JAX・Julia・Rustは将来候補です。

**コード・記事・検証記録：** [github.com/okamasaya/DIY_AutoML](https://github.com/okamasaya/DIY_AutoML)

開発版0.4.0a7／Python 3.12・Linux CPUで開発・wheel環境とも各200テスト通過。掲載データは繰り返し参照した開発例です。
