# UC_AutoMaiL α版の紹介　モデル比較と評価の不確かさをPythonで記録する

複数のモデルを試した後、どのデータで候補を選び、どのデータで最終評価したかを後から確かめたいことがあります。スコアが少し違うときには、評価に使った件数や、スコアのばらつきも見ておきたいところです。

このために **DIY_AutoML** として開発してきたツールを、Pythonパッケージ **UC_AutoMaiL** として試験配布しています。分類モデルの比較から始めて、入力の点検、評価の区間、実行時の条件を一緒に保存できるようにしました。名前の `UC` は、開発の出発点になった Uncertainty（不確かさ）と、`AutoMaiL`はAuto Machine intelligence Learningの言葉遊びして繫げたことより由来します。 [DIY_AutoMLを始めた経緯](https://zenn.dev/okamasaya/articles/diy-automl-evaluation-framework)

## α版でできること

| 試したいこと | 用意するもの | 確認できること |
| --- | --- | --- |
| CSVを点検する | 特徴量やラベルを含むCSV | 欠損、重複、入力列、クラスの件数 |
| 分類モデルを比べる | 数値特徴量と正解ラベル | 5候補の交差検証、選んだモデルの保留評価、評価値の区間 |
| 時系列の状態を推定する | 時系列の観測と、推定する状態に合わせたモデル | カルマンフィルタ系や粒子フィルタによる推定、EKF・UKFの残差の診断 |
| グラフ上のノードを分類する | ノードの特徴量、辺、学習に使うラベル | GCNと表形式モデルの分類結果の比較 |

CSVの分類では、決定木、ランダムフォレスト、ロジスティック回帰、SVM、k近傍法を比較できます。評価用に取っておいた行は、候補を選んだ後の採点に使います。実行条件と分割、正解ラベル、予測を保存するので、図付きExcelで見つけた違いを元の記録までたどれます。 [ソースと開発記録](https://github.com/okamasaya/DIY_AutoML)

## 評価の区間に何が入るか

分類のブートストラップ区間は、選んだ学習済みモデルの予測と、保留データで観察したクラスごとの件数を固定して計算します。保留データの中で行を復元抽出すると、同じモデルでも評価値が変わります。その幅を点数と並べて確認できます。データ分割や学習条件を変えたときの影響を知りたい場合は、それらを変えた実験も行います。 [DIY_AutoMLの評価設計](https://zenn.dev/okamasaya/articles/diy-automl-ds-uncertainty)

状態推定では、EKF・UKFで観測から次の状態を推定した後、予測観測と実際の観測の差を点検できます。`0.4.1a0` では、差の大きさを見るNISや、時間方向の残り方を見る自己相関とLjung–Boxを追加しました。真値があるシミュレーションでは、推定誤差を成分ごとに標準偏差で割ったpullと、共分散を使って状態全体の推定誤差を評価するNEESも計算できます。 [α版の機能と導入手順](https://test.pypi.org/project/uc-automail/0.4.1a0/)

## 最初に試すならIris

PCのCPUとPython 3.12以降で、小規模な分類から試せます。現在の配布先はTestPyPIです。版を `0.4.1a0` に指定し、パッケージのwheelをTestPyPIから、依存ライブラリをPyPIから取得します。具体的なコマンドは配布ページに載せています。 [UC_AutoMaiL 0.4.1a0の配布ページ](https://test.pypi.org/project/uc-automail/0.4.1a0/)

インストールした環境では、次のように読み込みます。以降の使用例では `uc_al` を使います。

```python
import uc_automail as uc_al

print(uc_al.__version__)
```

まずはIrisの点検、5モデルの比較、図付きExcelの順に試すと、モデルの選び方と、手元に残る評価結果を確認できます。使ったOSやPythonの版を添えて感想をもらえると、α版の改善に活かせます。 [不具合や改善点の報告先](https://github.com/okamasaya/DIY_AutoML/issues)
