# 引継ぎと再開の入口

更新日：2026-11-10（日本時間）

## 当面の運用

引継ぎ資料は、Gitと作業したチャット（スレッド）の両方に残す。リポジトリへ再接続した際、この文書から状態を確認して再開できる形にする。この運用は本人が見直すまで継続する。

- Gitには、合意した方針、完了した作業、成果物の場所、実施した確認、未完了事項、次の一手を残す。
- チャットの終了報告にも、その要約、引継ぎ文書へのリンク、コミット・リモート反映の状態、次に始めることを残す。
- ローカルでの保存、コミット、リモートへの反映、検証の実施を区別して記録する。保存できなかったものはチャットで所在と状態を伝える。
- 方針の変更は、理由と変更点をGit・チャットの双方へ記録する。
- この文書は最新状態へ更新する入口とし、詳しい設計や過去の経緯は関連文書とGit履歴へつなぐ。

## 再接続したときの読み方

1. 接続先のリポジトリ、ブランチ、コミット、未コミット変更、リモートの更新を確認する。本人のWeb編集や別の作業と照合する。
2. 本書の「現在の引継ぎ」を読み、[修正方針](REVISION_POLICY_20261110.md)と[ROADMAP](ROADMAP.md)で作業範囲を確認する。
3. 関連する前のチャットが参照できれば、終了報告とコミットを照合する。最新の本人の指示を優先する。
4. 完了済みの作業を繰り返さず、未完了の次の一手から再開する。状態が変わっていれば、本書を更新する。
5. 実行が必要な作業では、依存関係と再実行手順を確認する。前の一時環境が残っていることは前提にせず、Git内のファイルや取得先から必要なものを揃える。

## 作業を区切るときの記録項目

| 項目 | 残す内容 |
| --- | --- |
| 目的と方針 | 今回の対象、決まったこと、方針変更の理由 |
| 完了 | 変更した内容と、参照するファイル・成果物 |
| 確認 | 実施したテスト・リンク確認等と結果。未実施は未実施と記録 |
| 保存状態 | 作業ブランチ、コミット、リモート反映、未コミット・未保存の有無 |
| 未完了 | 残る課題、途中の状態、本人の作業との分担 |
| 次の一手 | 最初に読むものと、次に行う具体的な作業 |

実装を伴う作業では、再開に必要な依存版・実行コマンド・入力や保存先も関連する手順へ残す。
