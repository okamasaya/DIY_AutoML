# 完了したことと、次に行うこと

2026年11月12日（日本時間）更新。対象は **0.4.0a7** です。11月8日までの基礎実装と、11月12日の記事・出力見本の整備を区別します。0.4.0a6の誤差評価を基礎に、DLバックエンド追加の準備を加えています。本書は現在の状態と推奨する作業順をまとめ、完了の範囲は各検証資料で区別します。直近の作業は[スレッドまとめ](THREAD_SUMMARY_20261112.md)を参照してください。

目的は、評価値とその不確かさを示し、データ量・品質・モデルの使い方について議論できるAutoMLを作ることです。現在の対応は数値特徴量・欠損なし・ラベル付きの分類CSVです。ULも外部診断用のtargetを必要とします。SL/DLとULの指標を混ぜた総合順位は作りません。

利用者別の完成形は、**ビジネス向け：使い勝手を重視した廉価版アプリ、DS向け：Pythonで駆動しPyPIで配布するパッケージ**です。共通の評価コアを使います。価格・提供方法やPyPI公開名は未確定で、公開レジストリへの配布は今後です。現在の基礎版の完了と、両者の完成目標を区別します。

## 次の1区切り：データ点検と評価条件の記録

次の実装対象として推奨するのは、上表の順序1です。この整理では実装を開始していません。版番号・日程は未確定です。

- 入力SHA256、行/列数、列型、欠損・非有限値、定義した重複、クラス別件数を記録する。
- 予測対象、予測時点、1行の意味、管理用ID/時刻列、ラベルの由来を利用者が明示できるようにする。行数やユニーク行数を独立標本数と呼ばない。
- ID/期間が与えられれば件数や範囲を集計し、与えられなければ不明とする。予測時点で利用可能かは勝手に推測しない。
- 学習できないCSVも、可能な範囲で点検理由を残す。点検によって重複削除や補完を自動実行する仕様にはしない。
- Excel/機械可読記録と検証器を用意し、正常例・欠損・重複・少数クラス・識別子なし等で確認する。元データを保持し、既存の学習・誤差評価との対応を保存する。

この区切りで確認するのは「何のデータで、どの評価ができるか」です。区間幅から量不足/品質不良を自動診断する機能ではありません。
