# 完了したことと、次に行うこと

2026年11月19日（日本時間）更新。**0.4.0a7** を基礎とした開発ブランチの状況を含みます。今回の区切りは、BP画面でCSVの点検から、分割条件を選ぶモデル比較と日本語Excelの保存までを実行できることです。 [BP版の分類評価マイルストーン](BP_CLASSIFICATION_MILESTONE_20261119.md)

目的は、評価値とその不確かさを示し、データ量・品質・モデルの使い方について議論できるAutoMLを作ることです。現在の対応は数値特徴量・欠損なし・ラベル付きの分類CSVです。ULも外部診断用のtargetを必要とします。SL/DLとULの指標を混ぜた総合順位は作りません。

利用者別の完成形は、**ビジネス向け：使い勝手を重視した廉価版アプリ、DS向け：Pythonで駆動しPyPIで配布するパッケージ**です。共通の評価コアを使います。価格・提供方法やPyPI公開名は未確定で、公開レジストリへの配布は今後です。現在の基礎版の完了と、両者の完成目標を区別します。

## 時系列の誤差評価：今後の課題（2026年11月12日追記）

現行版では日付順の分類評価に加え、数値1系列でカルマンフィルタの1ステップ先予測・状態推定と区間の被覆率を扱う。予測の先の長さを変えた評価や、性能推定の区間は今後の課題とする。 [カルマンフィルタの実行手順](UNCERTAINTY_DESIGN.md#カルマンフィルタで数値の時系列を点検する)

- BP向けには、売上・問い合わせ等の過去の推移や季節性を把握するトレンド分析も予定に含める。日時・集計単位・欠測・記録の定義を確認し、過去の傾向、将来予測、施策の因果効果を分けて説明する。
- 予測時点、予測する先の長さ、時間間隔、系列ID、利用可能な特徴量を記録する。
- 過去から未来へのrolling-origin評価を設計し、前処理・設定選択への未来情報の混入や、重なる予測期間を点検する。
- 将来の値の予測区間と、MAE/RMSE等の性能推定の区間を分ける。予測する先・期間・系列別に性能、経験被覆率、区間幅を確認する。
- 性能指標の区間は、block bootstrap等の依存を保つ方法を候補とし、ブロック長や定常性などの条件を検討する。現行の行単位再標本化をそのまま使わない。
- 図には水準・予測する先・評価期間・対象を添え、最大誤差の保証としない。時点別の区間と経路全体の同時被覆、分布変化・系統/数値誤差の確認を区別する。

実装順・対象モデル・期限を今回確定した意味ではない。DS記事では「今後の課題」として説明し、実装と実測の検証は後続にする。

## データ点検と評価条件の記録

`audit-data` を追加した。CSVの点検結果を先に確認し、必要な修正をしたデータを改めて評価に使う。任意でParquetまたはDuckDBに変換し、入力のハッシュ・列型・行数を記録した中継ファイルを保存できる。 [出力・確認手順](DATA_AUDIT.md)

- 入力SHA256、行/列数、列型、欠損・非有限値、定義した重複、クラス別件数を記録する。
- 予測対象、予測時点、1行の意味、管理用ID/時刻列、ラベルの由来を利用者が明示できるようにする。行数やユニーク行数を独立標本数と呼ばない。
- ID/期間が与えられれば件数や範囲を集計し、与えられなければ不明とする。予測時点で利用可能かは勝手に推測しない。
- 学習できないCSVも、可能な範囲で点検理由を残す。点検によって重複削除や補完を自動実行する仕様にはしない。
- Excel/機械可読記録と検証器を用意し、正常例・欠損・重複・少数クラス・識別子なし等で確認する。元データを保持し、既存の学習・誤差評価との対応を保存する。

この区切りで確認するのは「何のデータで、どの評価ができるか」です。区間幅から量不足/品質不良を自動診断する機能ではありません。
