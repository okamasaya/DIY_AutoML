# 次の作業

## 利用者が示した優先軸

DIYの主目的は、実行結果に誤差評価を含め、データ量・品質について議論することです。新しいモデルの追加より、評価単位/データ点検、既存モデルの学習曲線、再学習・選定をやり直す変動、グループ/時間分割を優先します。現状の条件付きtest区間だけでは量不足と品質問題を識別できません。設計と未実装範囲は `docs/UNCERTAINTY_DESIGN.md` を参照してください。

定量化した値を用途に合う選定へ結び付け、DS以外へ伝えることもテーマです。目的・許容する誤り・制約を定める人の役割と、計算・比較・記録を自動化する範囲を分けます。費用評価/閾値最適化、分かりやすい件数表示、利用者の理解確認は設計段階です。
