# 親記事と利用者別の子記事（方針記録）

利用者は親記事の温度感を確認済みです。AutoML本体の整備を優先し、完成した機能に合わせて記事・利用入口を分けます。この方針を今回のGit保存に含めます。

## 親記事

現行の `articles/diy-automl-evaluation-framework.md` をリポジトリ紹介の親記事とします。目的、何を比較できるか、評価の考え方、検証範囲と限界を伝えます。レビュー時点の0.4.0a4原稿を保全し、完成版の仕様が固まった時点で版・導入例を更新し、子記事への案内を追加します。現在published=falseで、Zennの公開操作は行っていません。

## DS向けの子記事

同じdiy_automlの共通関数を、Notebookでもターミナルでも選んで使える詳細な使い方を扱います。CSV/targetの指定、selectとtuneの選定手順、UL/DL反復の設計、設定・seed・保存配列・manifest、結果検証、図付きExcelの生成を説明します。GUIだけに閉じず、再現と検査ができる入口を維持します。

NotebookとCLIで評価の意味や前処理が変わらないことが前提です。記事を書く前に実行経路を検証し、未実装の機能や検証していないOSを完成済みとは説明しません。

## ビジネスパーソン向けの子記事とアプリ

データファイルを渡し、結果のExcelを受け取る入口を目指します。将来のアプリは共通CSV読込・評価・出力関数を呼び、別の学習ロジックを画面内に作りません。target列の指定、受け付けるデータ形式、実行状態・失敗理由、結果のダウンロードを、利用者が扱える形で示します。

現状は数値・欠損なし・ラベル付き分類CSVが対象です。将来アプリもこの実装範囲を明示し、モデルを実用途へ推奨・採用する判断を自動化したかのようには説明しません。ファイルアップロードからExcel出力までの画面と、実データでの使い方は、アプリが実装・検証できてから子記事にします。

## 順序

1. AutoML本体と結果のExcel出力・図・検証を仕上げる。
2. 同じ機能をNotebook/CLIから使えることを確認する。
3. 親記事の対象版を更新し、DS向けの詳細記事を作る。
4. 共通関数に接続するアプリを実装・検証し、ビジネス向けの記事を作る。
5. 利用者による原稿確認後にZennで公開する。

この記録は実装方針です。子記事やアプリを今回完成・公開した意味ではありません。mainへのマージ、default branch変更、ライセンス選定、Zenn連携設定は別の判断として残します。
