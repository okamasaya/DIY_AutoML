# 親記事と利用者別の子記事（方針記録）

利用者は親記事の温度感を確認済みです。AutoML本体の整備を優先し、完成した機能に合わせて記事・利用入口を分けます。この方針を今回のGit保存に含めます。

## 親記事

現行の `articles/diy-automl-evaluation-framework.md` をリポジトリ紹介の親記事とします。目的、何を比較できるか、評価の考え方、検証範囲と限界を伝えます。温度感を確認した0.4.0a4原稿と、そのまま保持した0.4.0a5実装時点の原稿はGit履歴に残ります。今回、対象版を0.4.0a5へ更新し、実装済みの図付きExcel入口と、モデルの新しさ・改善幅についての参考文献を追加しました。現在published=falseで、Zennの公開操作は行っていません。

親記事の主張は「新しいモデルでも、改善幅はデータ・評価条件・計算予算に依存する」とします。従来手法が有力な報告と新手法が改善した報告の両方を引用し、「最新モデルでも結果は変わらない」「既存の5モデルで最新モデルと同等」とは断定しません。文献の結果と、このリポジトリ自身の実測を分けます。

## DS向けの子記事

同じdiy_automlの共通関数を、Notebookでもターミナルでも選んで使える詳細な使い方を扱います。CSV/targetの指定、selectとtuneの選定手順、UL/DL反復の設計、設定・seed・保存配列・manifest、結果検証、図付きExcelの生成を説明します。GUIだけに閉じず、再現と検査ができる入口を維持します。

NotebookとCLIで評価の意味や前処理が変わらないことが前提です。記事を書く前に実行経路を検証し、未実装の機能や検証していないOSを完成済みとは説明しません。

DS向けは、既存モデルから新しいモデルまで比較対象を広げられる構成を目指します。追加モデルは任意導入の候補として扱い、すべての最新モデルを現時点で網羅する約束にはしません。Iris/Wine/Breast Cancerは馴染みのある既存の開発例として維持します。追加モデル・データの実装と検証、特に計算資源を多く使う実験は `docs/MODEL_VALIDATION_TODO.md` に保留します。

## ビジネスパーソン向けの子記事とアプリ

データファイルを渡し、結果のExcelを受け取る入口を目指します。将来のアプリは共通CSV読込・評価・出力関数を呼び、別の学習ロジックを画面内に作りません。target列の指定、受け付けるデータ形式、実行状態・失敗理由、結果のダウンロードを、利用者が扱える形で示します。

現状は数値・欠損なし・ラベル付き分類CSVが対象です。将来アプリもこの実装範囲を明示し、モデルを実用途へ推奨・採用する判断を自動化したかのようには説明しません。ファイルアップロードからExcel出力までの画面と、実データでの使い方は、アプリが実装・検証できてから子記事にします。

ビジネス向けは主要モデルによる小規模な比較を中心にし、モデル数を増やすことを利用手順の前提にしません。標準の利用例はCPUで扱える範囲を目指し、DLや追加の重いモデルは必要性がある場合の任意候補とします。具体的なUIの標準モデルセットは、業務データで確認してから決めます。現在の共通関数の5モデルや既定動作を、この方針記録だけで変更するものではありません。

検証データは「何を入力し、何を予測・分類するか」を説明しやすく、少ない列・小規模・機密情報なしを優先します。営業案件の成約有無を扱う架空の説明用CSVと、商品カテゴリ別年間購入額が分かる[UCI Wholesale customers](https://archive.ics.uci.edu/dataset/292/wholesale+customers)を候補にします。採用・データ作成・実行検証は未実施です。実データと架空データ、説明用検証と業務上の効果検証は区別します。

Wholesale customersは440顧客・6つの商品カテゴリ別購入額とChannel/Regionを持つ公開データです。クラスタ分析では購入額を特徴量とし、Channel/Regionを正解クラスタと決めつけません。現在のULはtargetが必須なので、ラベルなしUL入口の整備か、外部診断用ラベルを明示した別の実験設計が必要です。Bank MarketingやOnline Retailは、カテゴリ処理・集約などが必要な後続候補とします。

## 順序

1. AutoML本体と結果のExcel出力・図・検証を仕上げる。
2. 同じ機能をNotebook/CLIから使えることを確認する。
3. 親記事の対象版を更新し、DS向けの詳細記事を作る。
4. 共通関数に接続するアプリを実装・検証し、ビジネス向けの記事を作る。
5. 利用者による原稿確認後にZennで公開する。

この記録は実装方針です。子記事やアプリを今回完成・公開した意味ではありません。mainへのマージ、default branch変更、ライセンス選定、Zenn連携設定は別の判断として残します。
