利用者は親記事の温度感を確認済みです。AutoML本体の整備を優先し、完成した機能に合わせて記事・利用入口を分けます。この方針を今回のGit保存に含めます。

追加依頼により、誤差評価を親記事の動機と評価方針として明記し、ビジネス向けは平易な説明と持ち込むデータとの対比、DS向けは推定条件・数式・保存結果まで踏み込む構成にしました。ビジネス向けの簡易版は計算量と説明を絞る意味で、評価の前提や重要な限界を省く方針ではありません。価格設定を決めたものでもありません。

原稿一次稿では、親記事を作り始めた疑問と実例から読む紹介文に整え、詳細な導入手順・CVフロー図はDS記事へ移しました。ビジネス記事は件数とデータの意味から読む構成を維持します。参考にする外部記事は未指定で、編集意図は[ZENN_EDITORIAL_NOTES.md](ZENN_EDITORIAL_NOTES.md)にまとめています。

現行の `articles/diy-automl-evaluation-framework.md` をリポジトリ紹介の親記事とします。目的、何を比較できるか、評価の考え方、検証範囲と限界を伝えます。温度感を確認した0.4.0a4原稿と、0.4.0a5実装時点の原稿はGit履歴に残ります。現在の親/DS記事の対象版は0.4.0a7で、図付きExcel、モデルの改善幅の参考文献、uncertaintyのSE・クラス別区間と手順、DLバックエンド追加の準備を反映しています。3本ともpublished=falseで、Zennの公開操作は行っていません。

利用者の追加依頼で、ホテル・カフェ券・再購入のQuick & dirty実験の要約も追記しました。既存モデルと単純ルールの比較であり、最新モデルの改善幅を測った実験ではありません。

親記事の主張は「新しいモデルでも、改善幅はデータ・評価条件・計算予算に依存する」とします。従来手法が有力な報告と新手法が改善した報告の両方を引用し、「最新モデルでも結果は変わらない」「既存の5モデルで最新モデルと同等」とは断定しません。文献の結果と、このリポジトリ自身の実測を分けます。

## DS向けの子記事

PyTorch追加の準備と、JAX・Julia・Rustの将来展望を追記しました。親/DS記事の現在の対象版は0.4.0a7です。TensorFlowのみ学習実装済み、PyTorchは共通境界を整える準備まで、JAXは利用者が未経験の検討候補、Julia/Rustは方式・時期未定の展望として扱います。DL_BACKENDS.mdと照合し、各backend/言語を対応済みと記載しません。

完成条件は「PyPIから導入し、説明どおりにモデル比較・誤差評価・結果の保存と検証まで実行できる」です。Notebook/CLI/Python API、公開APIと互換性、サンプル手順、対応環境と任意DL依存を整えます。配布名候補diy-automlの利用可否は未確認です。TestPyPIでの確認→PyPIのα版→正式版の順を想定します。現在のwheel検証と、公開レジストリからの導入成功を区別します。

同じdiy_automlの共通関数を、Notebookでもターミナルでも選んで使える詳細な使い方を扱います。CSV/targetの指定、selectとtuneの選定手順、UL/DL反復の設計、設定・seed・保存配列・manifest、結果検証、図付きExcelの生成を説明します。GUIだけに閉じず、再現と検査ができる入口を維持します。

誤差評価の詳細下書き `articles/diy-automl-ds-uncertainty.md` を作成しました。推定対象、CV平均とfold SD、paired percentile bootstrapとSE、層化/通常の行抽出、有限反復・行の依存・未観測クラスの制約、学習seedと数値誤差の区別、系統的な偏り、Notebook/CLIの共通経路を扱います。0.4.0a6の実装済み範囲と、学習手続き全体・系統/数値誤差など今後の設計を区別します。全コマンドの詳細な利用ガイドは引き続き今後です。

NotebookとCLIで評価の意味や前処理が変わらないことが前提です。記事を書く前に実行経路を検証し、未実装の機能や検証していないOSを完成済みとは説明しません。

DS向けは、既存モデルから新しいモデルまで比較対象を広げられる構成を目指します。追加モデルは任意導入の候補として扱い、すべての最新モデルを現時点で網羅する約束にはしません。Iris/Wine/Breast Cancerは馴染みのある既存の開発例として維持します。追加モデル・データの実装と検証、特に計算資源を多く使う実験は `docs/MODEL_VALIDATION_TODO.md` に保留します。

## ビジネスパーソン向けの子記事とアプリ

テーマは「どの値を測れば、用途に合うモデルの選定と活用へつながるか」「DS以外の人にも、その根拠と限界が伝わるか」です。DS向けと同じ評価を使い、先頭には対象・拾えた件数・見逃し・誤案内・単純ルールとの差を示し、統計指標や反復の詳細は別シートで追える構成を目指します。表示の分かりやすさや訴求効果は、モデルの性能とは別に利用者確認が必要です。具体的な指標と自動化の範囲はdocs/UNCERTAINTY_DESIGN.mdに記録しています。

既存のビジネス記事には「誤差とは？」を追加し、予測の失敗件数、数値の揺れ、調べた対象の偏りを短く説明しました。持ち込むデータと公開例を対比する表で、予測の目的、1行の意味、利用可能時点、困る誤り、単純ルール、別期間・顧客での検証を確認します。入力CSVの点検プレビューから実装を始めました。

データファイルを渡し、結果のExcelを受け取る入口を目指します。将来のアプリは共通CSV読込・評価・出力関数を呼び、別の学習ロジックを画面内に作りません。target列の指定、受け付けるデータ形式、実行状態・失敗理由、結果のダウンロードを、利用者が扱える形で示します。

現在の学習機能は数値・欠損なし・ラベル付き分類CSVを扱います。点検画面では文字列や欠損のあるCSVも読み取り、確認項目として示します。学習に使う列の選択からモデル比較・日本語の評価Excelを受け取る流れまでWindowsで検証しました。 [画面の使い方](DATA_AUDIT.md#データ点検の画面を使う)

今回の追加依頼で、画面手順に先行する実験解説の下書き `articles/diy-automl-business-three-experiments.md` を作成しました。3テーマの実測と一般的な見方の比較を扱い、published=falseです。データ投入アプリや、その画面の操作手順を完成した意味ではありません。

ビジネス向けは主要モデルによる小規模な比較を中心にし、モデル数を増やすことを利用手順の前提にしません。標準の利用例はCPUで扱える範囲を目指し、DLや追加の重いモデルは必要性がある場合の任意候補とします。具体的なUIの標準モデルセットは、業務データで確認してから決めます。現在の共通関数の5モデルや既定動作を、この方針記録だけで変更するものではありません。

BP向けの初回結果は、主要モデルのCPU比較を入口とし、何件を正解・誤分類したかと、評価の幅を示す。Annealing checkはDS向けの任意実行とする。BP向けにも加えるかは、削減できる列の取得・計測の負担、予測への影響、想定端末での所要時間を材料に判断する。粒の特徴から品種を分類する軽量な実習を用意した。 [SeedsとRaisinの出典・実行例](../data/reference/README.md)

学習前の点検と任意の圧縮は、CLIの `prepare-bp` とPythonの `prepare_bp_csv` から使える。Windows画面 `bp-preview` でCSVと正解列を指定し、使う列を選んで抽出後のデータを再点検できる。元CSVと抽出後の比較を表示し、Excelと抽出CSVを保存する。圧縮を選ぶと作業用Parquetを作り、前後のサイズを表示する。 [画面の起動と使い方](DATA_AUDIT.md#データ点検の画面を使う)

Iranian Churnの実データで、点検からモデル比較とExcel保存までを計測した。1顧客1行の3,150行から使う列を選び、同じ入力で解約ラベルが異なる組などを確認して2,754行で比較した。この例から、BP版の初回利用で見せる内容を具体化した。 [実測値と再現手順](../experiments/bp_churn_pilot/README.md)

| 場面 | 画面で見せる内容 |
| --- | --- |
| CSVを選ぶ | 1行が表すもの、正解列、予測する時点、予測に使う列を確認できる |
| 学習前に確認 | 読み取った件数・欠損・正解ラベルの件数を表示する。使用列が決まったら同一入力やラベル不一致の組を確認し、対象が変わる場合は前後の件数と判断理由を残す |
| CPUで実行 | 点検・任意の圧縮・学習・Excel保存の進行と、停止した工程の理由を示す |
| 結果を見る | 保留テストの件数、拾えた件数、見逃しと誤検知、学習側多数派ルールとの比較を先頭に置く。分割条件・評価区間・詳細Excelを結果から開ける |

検証データは「何を入力し、何を予測・分類するか」を説明しやすく、少ない列・小規模・機密情報なしを優先します。公開例は `docs/BUSINESS_DATASETS.md` に調査しました。実行した題材はホテル、カフェ券、Online Retailの簡易実験と、Iranian Churnの処理負荷検証です。[Wholesale customers](https://archive.ics.uci.edu/dataset/292/wholesale+customers)、CDNOW、IBMの架空企業教材も候補です。

Wholesale customersは440顧客・6つの商品カテゴリ別購入額とChannel/Regionを持つ公開データです。クラスタ分析では購入額を特徴量とし、Channel/Regionを正解クラスタと決めつけません。現在のULはtargetが必須なので、ラベルなしUL入口の整備か、外部診断用ラベルを明示した別の実験設計が必要です。Bank MarketingやOnline Retailは、カテゴリ処理・集約などが必要な後続候補とします。

## 順序

本体の評価基盤の具体的な次の順序は[ROADMAP.md](ROADMAP.md)へ統一します。以下は記事と入口の段階で、完了済みの3下書きも更新しながら進めます。

1. AutoML本体と結果のExcel出力・図・検証を仕上げる。
2. 同じ機能をNotebook/CLIから使えることを確認する。
3. 親記事の対象版を更新し、DS向けの詳細記事を作る。
4. 共通関数に接続するアプリを実装・検証し、ビジネス向けの記事を作る。
5. 利用者による原稿確認後にZennで公開する。
