# 誤差評価を中心にした目的と次の設計

2026年11月8日（日本時間）、利用者がDIYした主目的として「MLの実行結果に誤差評価を含め、データ量不足なのか、品質など別の問題なのかを議論したい」と明示しました。モデル追加より、この議論に必要な評価と記録を優先します。0.4.0a6では保存済みSL/DL指標のbootstrap SE・区間・クラス別評価を実装しました。本書では現状と未実装の設計を区別します。手順は[METRIC_UNCERTAINTY_GUIDE.md](METRIC_UNCERTAINTY_GUIDE.md)です。

## 目的

点のスコアだけでなく、評価条件と不確かさの由来を示し、「追加収集を検討するか」「特徴量や正解ラベルを点検するか」「評価対象や分割を見直すか」を議論できる道具を目指します。

予測を外す大きさ/頻度と、その誤り率やF1をどれくらい正確に推定できているかは別の量です。不確かさの小さい低スコアもあり、不確かさの大きい高スコアもあります。区間幅だけから、データ量不足とデータ品質の問題を一意に識別することはできません。

利用者が続けて示したテーマは、データを使う/使わないという判断から先に進み、「どの指標で定量化し、用途に合うモデル活用とAutoMLの選定へつなぐか」「DS以外にもどこまで伝わるか」です。統計的な評価、業務上の判断、説明の分かりやすさを、それぞれ検証する設計とします。

## 統計・計算・系統的な偏りを区別する

利用者は誤差評価の範囲として統計・計算・系統誤差までを明示しました。予測の失敗と、性能推定の不確かさを区別したうえで、次を別に記録します。全要因を独立な成分に分解できる、または合成した1本の区間で網羅できるという設計ではありません。

| 観点 | 記録・比較するもの | 現在と未実装の範囲 |
| --- | --- | --- |
| 統計的な不確かさ | 標本、独立な評価単位、クラス件数、学習/選定手続きの変動 | 固定モデルの条件付きtest区間と一部反復まで。学習曲線・手続き全体の反復・グループ/時間評価は今後 |
| 学習手順の変動 | 初期化、shuffle、データ抽出等のseedと固定した条件 | DL/UL等の入口で指定した反復。丸め誤差とは呼ばない |
| 数値計算誤差 | dtype、収束判定、ソルバ、ライブラリ/計算基盤、目的関数・予測の差 | 一部の収束情報・失敗状態・条件の保存まで。精度/許容値の感度比較は未実装 |
| 系統的な偏り | 測定の校正ずれ、ラベル、対象の選び方、リーク、群や期間の違い | 個別実験での制約確認まで。汎用監査や外部基準との照合は今後 |

数値誤差の検証では入力・分割・学習seedを固定し、比較可能な精度や許容値を変えて、収束と予測の変化を対応付けます。ソルバの変更で収束先も変わりうるため、観測差をすべて丸め誤差に帰属させません。独立wheelでの一致は実装・配布の再現確認であり、共通する誤差の不在を証明しません。

系統的な偏りには原票、独立した再判定、追加測定、別集団/別期間などの照合が必要な場合があります。不明な偏りを0として扱わず、確認済み・懸念・未確認を分けます。bootstrapの反復数や行数を増やすだけで補正できるとは説明しません。

この内容は親記事の動機と評価方針、ビジネス記事の短い説明と持ち込みデータとの対比、DS記事の推定対象・式・条件を追う説明へ反映しました。ビジネス向け簡易版も同じ根拠に基づき、計算量と説明を必要なところから使う設計とします。表示・入力アプリや数値計算感度評価を今回実装したものではありません。

## 定量化からモデル活用への対応（設計）

以下は主にSL分類の整理です。ひとつの総合品質点にまとめず、測った値・未確認項目・判断への関係を並べます。

| 判断したいこと | 定量化する候補 | 選定・説明へのつなぎ方 |
| --- | --- | --- |
| 何件の情報があるか | 行数、クラス別件数、識別できる独立した顧客/回答者数、期間のカバレッジ | 行数だけで十分とは判定しない。識別できない独立件数は不明とする |
| 入力と正解をどこまで信頼できるか | 列別欠損率、定義した重複率、値/単位の不整合件数、独立に点検したラベルの不一致率と点検件数 | 外れ値を自動で不良扱いせず、確認箇所を示す。モデルの予測不一致をそのままラベル誤り率にはしない |
| 何をどれだけ間違えるか | confusion matrix、陽性precision/recall、macro F1、必要に応じPR曲線等。多数派/業務ルールとの差 | 見逃しを重視するか、誤案内を減らしたいかで目的を決める。どの指標も万能な採用基準にはしない |
| 同じ結論が安定するか | 条件付き指標区間、学習曲線、再学習・選定の反復分布、グループ/時間分割での変化 | 不確かさの対象と未包含の変動を明記。狭い区間だけで良質・十分とは判定しない |
| 確率を判断に使えるか | 確率の総合的な誤差を測るBrier/log loss、校正曲線と各区間の件数 | 「80%と出す群で約80%が陽性か」を別データで確認。Brierだけを純粋な校正誤差とは呼ばない。確率は指標のCIとも別 |
| 業務で使う価値があるか | 業務側が定義した誤りの費用、対象件数・処理能力、実行時間・メモリ。測定できる場合の施策効果 | 費用・対象・制約を先に決め、その範囲でモデルと判定閾値を比べる。実効果や費用が不明なら利益は未評価とする |

評価指標は[予測の目的に合わせて選ぶ](https://scikit-learn.org/stable/modules/model_evaluation.html)必要があります。確率の予測と、その値から行動を決める判定閾値は別の問題です。[判定閾値の説明](https://scikit-learn.org/stable/modules/classification_threshold.html)。確率の校正については[公式資料](https://scikit-learn.org/stable/modules/calibration.html)を参照します。

「最適」は、指定したデータ・候補・前処理・計算予算・評価指標・業務制約の中での選定です。モデル名に普遍的な最適性があるとは説明しません。現行select/tuneは指定した4指標のいずれか（既定macro F1）で選びます。上記の費用評価・確率校正・判定閾値の最適化・汎用の品質監査は未実装です。

## AutoMLで自動化する判断と、人が決める前提

人が決める前提は「誰/何を、いつの情報で、何のために予測するか」「見逃しと誤案内のどちらをどれだけ許容するか」「対象件数や費用」です。費用が分からない場合は仮定を勝手に埋めず、まず誤りの件数を示します。

自動化する側は、その前提の記録、適切な分割、学習側だけでの前処理・比較・必要な閾値選択、不確かさの集計、単純ルールとの比較、選定候補1つの最終評価です。最終testで目的・費用・閾値・候補を選び直しません。条件を満たす根拠がない場合は、必ずモデルを推奨する仕組みにせず、判断を保留する理由を示す設計です。

ULは予測ラベルの正誤とは別です。内部構造指標、初期化・データの変化に対する割当の一致、グループの説明と業務での使い道を別に見ます。内部指標が高いだけで採用価値があるとはしません。

## DS以外への表示と訴求の確認（未実装）

DS向けには条件・指標・全反復・配列・計算方法を保持します。ビジネス向けの先頭は「何に使う想定か」「何件を拾い/見逃し/誤って対象にしたか」「単純な判断よりどこが変わったか」「未確認事項と次に確認するデータ」とし、詳細を別シートへ続ける案です。同じ結果を、異なる詳しさで説明します。

今回のカフェ券では、保留した400回答のうち受取と判定した205件が、受取回答139件・拒否回答66件でした。受取回答なのに見逃したのは57件です。これはF1=0.692を具体的な件数に置き換えた説明例で、実際の来店数や施策売上ではありません。このデータでは回答者の独立性にも制限があります。

費用が定義されれば誤案内・見逃し等を重み付けして比べられますが、この調査回答だけで実際の機会損失や利益は算定しません。予測の正しさと、介入による効果を区別します。

どこまで伝わるかはモデルスコアで測れません。将来の利用者確認では、対象・誤り件数・限界・次に取る行動を説明し直せるか、単純ルールとの違いを読み取れるか、結果を過信していないかを確認します。読者の理解度・利用意向の測定は未実施で、訴求効果を実証済みとはしません。

## 現在できることと、その範囲

| 出力・入口 | 動かすもの/観察するもの | 含まないもの・解釈上の範囲 |
| --- | --- | --- |
| 点指標・confusion matrix | 正解と予測の対応 | 原因の特定、業務施策の因果効果 |
| select/tuneのtest bootstrap区間 | 学習済みモデルを固定し、観測した正解クラス別件数を保ってtest行を再標本化 | 学習・選定・再学習の変動、クラス割合の変動、分布の変化。依存する行を独立な標本とは扱えない |
| uncertainty（0.4.0a6） | 保存済みSL/DLの4指標とクラス別指標のbootstrap SE・区間。クラス件数固定/通常の行再標本化を選択 | 固定モデルの標本変動。学習・選定、群/時間依存、分布変化、系統/数値誤差は含まない。通常方式も行の独立性は必要 |
| CVのfold SD | 学習/validationの構成が変わったときの記述的なばらつき | 独立標本のSDとは限らず、SD/√fold数をそのままSEMや95%CIにしない |
| repeat-dl | 同じ分割とscalerで初期化・shuffleを変える | 学習データそのものの不足/品質の診断、分割を変えた変動 |
| repeat-ul | 同じデータで初期化seedを変える | データを取り直したときの変動、クラスタの業務上の有用性 |
| subsample-ul | データの一部を非復元抽出し、標準化とクラスタリングをやり直す | 原因の一意な特定。依存する反復対から独立標本のSEM/CIは作らない |

今回のホテルのtest F1=0.527と区間0.477–0.576も、固定した学習済みモデルと観測クラス件数に条件付きの値です。この幅から「2,000行では不足」「原本の品質が悪い」のどちらかを決めることはできません。

区間が狭くても、正解ラベルの誤り・リーク・代表性の不足・同一人物の繰返しが見逃されていれば、適切な評価になるとは限りません。今回のカフェ券は複数回答の調査ですが回答者IDがなく、行単位の分離/区間から新しい回答者への性能を主張できません。

## 量と品質を議論するために追加する観察

| 観察されるパターン | 検討する方向 | 断定できないこと |
| --- | --- | --- |
| 学習件数を増やすとvalidation性能が伸び、反復のばらつきも減る | 同じ対象集団からの追加収集が役立つ可能性 | 新しい期間や別集団でも同じ改善が出る保証 |
| 学習件数を増やしても、低い性能で頭打ちになる | 特徴量の情報量、モデル/設定の適合、ラベル、そもそもの予測困難さを点検 | データ品質が悪い、またはデータ量が絶対に十分という結論 |
| 行のランダム分割では高く、顧客/施設/時間を分けると落ちる | 同一対象の共有、情報漏れ、対象集団の違い、分布変化を点検 | 単純なデータ不足だけが原因という結論 |
| 反復や対象属性で結果が大きく揺れる | クラス別/グループ別の独立件数と代表性、誤りの偏りを点検 | 全体の行数だけで必要件数を決めること |

学習曲線は、指定したモデル・特徴量・対象集団の範囲でデータ増加を調べるものです。観測していない件数の性能や、データ品質そのものを保証する機能にはしません。[scikit-learnの学習曲線の説明](https://scikit-learn.org/stable/auto_examples/model_selection/plot_learning_curve.html)

## 次の優先順（未実装）

1. **評価単位とデータ点検の記録**。行数に加え、クラス別件数、識別できる顧客/回答者/施設等の数、観測期間、欠損、重複、単位、ラベルの由来、予測時点を記録します。外れ値を自動的に不良データとはしません。識別できない依存や不明な測定過程は不明と表示します。
2. **既存モデルごとの学習曲線**。最終testを触らず、学習側だけで件数を段階的に増やします。同じvalidationに対応する学習部分集合は入れ子にし、前処理は各部分集合の学習だけでfitします。trainとvalidationのスコア、反復ごとの全値、SD等を保存します。初期化と抽出のseedを分け、まずCPUで小規模に確認します。
3. **再学習・選定をやり直す変動**。固定モデルの学習曲線と、候補選定からやり直すAutoML全体の曲線を別に扱います。後者では外側で評価対象を保留し、内側だけで前処理とCV選定を行います。外側の結果を見て候補や設定を選び直しません。[nested CVの目的](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)
4. **グループ/時間を考慮する評価**。顧客や回答者を共有する場合はグループ、将来を問う場合は時間を分けます。区間の再標本化単位も評価単位に合わせます。識別子がないデータでは、できない検証をできたことにしません。
5. **原因が既知の小実験で検証**。件数・ラベルノイズ・情報の少ない特徴量等を制御したデータで、表示と解釈が目的に合うかを確かめます。そこでの挙動を、そのまま実データの原因特定能力の証明とはしません。

反復数を増やすことと独立データを増やすことは別です。重なる分割や反復からの単純なSEM/CIは使いません。範囲や分位点を示す場合も、記述的な反復分布なのか、どの仮定に基づく信頼区間なのかを明記します。最良のseed・分割・件数をtestで選びません。

既に考察に使った3業務テーマは開発例です。そこに後から別の分割seedを振るだけで未見の外部検証と呼び直しません。学習曲線もまず開発側の診断として扱い、最終確認に使う別期間/別データの位置付けは事前に決めます。

正解ラベルや特徴量の測定誤りを判断するには、原票の照合、専門家の再確認、追加測定などが必要になることがあります。現状の観測データとモデル指標だけで、品質・モデルの不適合・本来的な予測困難さを完全に分解できるとは説明しません。

## 差別点としての伝え方

「他のAutoMLは誤差評価をしない」という市場全体の断定は使いません。[H2OはCVごとの指標の安定性確認](https://docs.h2o.ai/h2o/latest-stable/h2o-docs/cross-validation.html)を説明し、[AutoGluonの時系列機能は予測分布の分位点](https://auto.gluon.ai/stable/tutorials/timeseries/forecasting-quick-start.html)を出します。CVのばらつき、将来の値の予測区間、評価指標の区間は別の量であり、これらの例だけで製品全体や分類機能の比較を完了した意味にもなりません。

伝える軸は「評価対象・条件・不確かさの由来を保存し、データ量・品質・学習の不安定さについて次に調べることを議論しやすくする」です。現行実装では条件付きtest区間と一部の反復を提供し、量に対する学習曲線や選定のやり直しを含む診断は今後です。指標の区間が付くことだけを独自性やデータ品質の自動診断の実証にはしません。
