# 誤差評価を中心にした目的と次の設計

2026年11月8日（日本時間）、利用者がDIYした主目的として「MLの実行結果に誤差評価を含め、データ量不足なのか、品質など別の問題なのかを議論したい」と明示しました。モデル追加より、この議論に必要な評価と記録を優先します。本書は現状整理と未実装の設計方針で、新しい診断機能を実装・検証した記録ではありません。

## 目的

点のスコアだけでなく、評価条件と不確かさの由来を示し、「追加収集を検討するか」「特徴量や正解ラベルを点検するか」「評価対象や分割を見直すか」を議論できる道具を目指します。

予測を外す大きさ/頻度と、その誤り率やF1をどれくらい正確に推定できているかは別の量です。不確かさの小さい低スコアもあり、不確かさの大きい高スコアもあります。区間幅だけから、データ量不足とデータ品質の問題を一意に識別することはできません。

## 現在できることと、その範囲

| 出力・入口 | 動かすもの/観察するもの | 含まないもの・解釈上の範囲 |
| --- | --- | --- |
| 点指標・confusion matrix | 正解と予測の対応 | 原因の特定、業務施策の因果効果 |
| select/tuneのtest bootstrap区間 | 学習済みモデルを固定し、観測した正解クラス別件数を保ってtest行を再標本化 | 学習・選定・再学習の変動、クラス割合の変動、分布の変化。依存する行を独立な標本とは扱えない |
| CVのfold SD | 学習/validationの構成が変わったときの記述的なばらつき | 独立標本のSDとは限らず、SD/√fold数をそのままSEMや95%CIにしない |
| repeat-dl | 同じ分割とscalerで初期化・shuffleを変える | 学習データそのものの不足/品質の診断、分割を変えた変動 |
| repeat-ul | 同じデータで初期化seedを変える | データを取り直したときの変動、クラスタの業務上の有用性 |
| subsample-ul | データの一部を非復元抽出し、標準化とクラスタリングをやり直す | 原因の一意な特定。依存する反復対から独立標本のSEM/CIは作らない |

今回のホテルのtest F1=0.527と区間0.477–0.576も、固定した学習済みモデルと観測クラス件数に条件付きの値です。この幅から「2,000行では不足」「原本の品質が悪い」のどちらかを決めることはできません。

区間が狭くても、正解ラベルの誤り・リーク・代表性の不足・同一人物の繰返しが見逃されていれば、適切な評価になるとは限りません。今回のカフェ券は複数回答の調査ですが回答者IDがなく、行単位の分離/区間から新しい回答者への性能を主張できません。

## 量と品質を議論するために追加する観察

| 観察されるパターン | 検討する方向 | 断定できないこと |
| --- | --- | --- |
| 学習件数を増やすとvalidation性能が伸び、反復のばらつきも減る | 同じ対象集団からの追加収集が役立つ可能性 | 新しい期間や別集団でも同じ改善が出る保証 |
| 学習件数を増やしても、低い性能で頭打ちになる | 特徴量の情報量、モデル/設定の適合、ラベル、そもそもの予測困難さを点検 | データ品質が悪い、またはデータ量が絶対に十分という結論 |
| 行のランダム分割では高く、顧客/施設/時間を分けると落ちる | 同一対象の共有、情報漏れ、対象集団の違い、分布変化を点検 | 単純なデータ不足だけが原因という結論 |
| 反復や対象属性で結果が大きく揺れる | クラス別/グループ別の独立件数と代表性、誤りの偏りを点検 | 全体の行数だけで必要件数を決めること |

学習曲線は、指定したモデル・特徴量・対象集団の範囲でデータ増加を調べるものです。観測していない件数の性能や、データ品質そのものを保証する機能にはしません。[scikit-learnの学習曲線の説明](https://scikit-learn.org/stable/auto_examples/model_selection/plot_learning_curve.html)

## 次の優先順（未実装）

1. **評価単位とデータ点検の記録**。行数に加え、クラス別件数、識別できる顧客/回答者/施設等の数、観測期間、欠損、重複、単位、ラベルの由来、予測時点を記録します。外れ値を自動的に不良データとはしません。識別できない依存や不明な測定過程は不明と表示します。
2. **既存モデルごとの学習曲線**。最終testを触らず、学習側だけで件数を段階的に増やします。同じvalidationに対応する学習部分集合は入れ子にし、前処理は各部分集合の学習だけでfitします。trainとvalidationのスコア、反復ごとの全値、SD等を保存します。初期化と抽出のseedを分け、まずCPUで小規模に確認します。
3. **再学習・選定をやり直す変動**。固定モデルの学習曲線と、候補選定からやり直すAutoML全体の曲線を別に扱います。後者では外側で評価対象を保留し、内側だけで前処理とCV選定を行います。外側の結果を見て候補や設定を選び直しません。[nested CVの目的](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)
4. **グループ/時間を考慮する評価**。顧客や回答者を共有する場合はグループ、将来を問う場合は時間を分けます。区間の再標本化単位も評価単位に合わせます。識別子がないデータでは、できない検証をできたことにしません。
5. **原因が既知の小実験で検証**。件数・ラベルノイズ・情報の少ない特徴量等を制御したデータで、表示と解釈が目的に合うかを確かめます。そこでの挙動を、そのまま実データの原因特定能力の証明とはしません。

反復数を増やすことと独立データを増やすことは別です。重なる分割や反復からの単純なSEM/CIは使いません。範囲や分位点を示す場合も、記述的な反復分布なのか、どの仮定に基づく信頼区間なのかを明記します。最良のseed・分割・件数をtestで選びません。

既に考察に使った3業務テーマは開発例です。そこに後から別の分割seedを振るだけで未見の外部検証と呼び直しません。学習曲線もまず開発側の診断として扱い、最終確認に使う別期間/別データの位置付けは事前に決めます。

正解ラベルや特徴量の測定誤りを判断するには、原票の照合、専門家の再確認、追加測定などが必要になることがあります。現状の観測データとモデル指標だけで、品質・モデルの不適合・本来的な予測困難さを完全に分解できるとは説明しません。

## 差別点としての伝え方

「他のAutoMLは誤差評価をしない」という市場全体の断定は使いません。[H2OはCVごとの指標の安定性確認](https://docs.h2o.ai/h2o/latest-stable/h2o-docs/cross-validation.html)を説明し、[AutoGluonの時系列機能は予測分布の分位点](https://auto.gluon.ai/stable/tutorials/timeseries/forecasting-quick-start.html)を出します。CVのばらつき、将来の値の予測区間、評価指標の区間は別の量であり、これらの例だけで製品全体や分類機能の比較を完了した意味にもなりません。

伝える軸は「評価対象・条件・不確かさの由来を保存し、データ量・品質・学習の不安定さについて次に調べることを議論しやすくする」です。現行実装では条件付きtest区間と一部の反復を提供し、量に対する学習曲線や選定のやり直しを含む診断は今後です。指標の区間が付くことだけを独自性やデータ品質の自動診断の実証にはしません。
