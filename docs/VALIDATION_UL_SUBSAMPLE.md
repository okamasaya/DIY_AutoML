# UL部分抽出の検証（0.4.0a3）

元資料からの再実装に、非復元部分抽出の安定性分析を追加した検証です。旧環境の0.4ソースを復元した結果ではありません。0.4.0a1.post1と0.4.0a2の資料・検証結果は上書きせず残しています。

## 検証対象

Iris/Wine/Breast Cancerの各データで80%を一様非復元抽出します。抽出seed42..51の10回、モデルseed42固定、KMeans/GMM/階層4linkage、k=2..10の54候補です。参照54fitと部分集合540fitの計594fitを1実行に含みます。前処理は全データ参照と各部分集合で独立にfitします。

全データ参照の54候補の全割当とscalerは、初回再実装版の保存済み単回UL結果と照合します。反復間の比較は共通元行だけ、参照との比較は部分集合の元行だけに制限します。単一クラスタの比較や少ない共通行は、ARI=1などとして採点しません。

## テストした内容

- 元行indexを並べ替えても正しく整列し、クラスタ番号の置換に対してARIが不変。
- 各部分集合の件数と非重複性、抽出seedでの再現、昇順保持、固定モデルseedとの分離。
- 全データ参照と各部分集合だけでscalerをfitし、既存の単回処理で同じ部分集合を学習した結果と一致。
- 共通行不足・単一クラスタの比較を未採点にする。
- 最初・途中のモデル例外、参照/部分集合の標準化例外で、部分結果と未実行・失敗段階を保存。
- GMMの収束フラグのみ記録し、他の手法では存在しない収束確認をtrueとしない。
- 保存後のindex、scaler、ラベル、参照ARI、反復対ARI、集計、状態、チェックサムの不整合を検出。
- 候補数・行数・特徴量数・パラメータ値の制限を確認。

既存のSL/UL/DL・選定・DL反復のテストも含めます。点ごとのSilhouette SDと部分集合間のSDを異なる列名で保存し、反復対から独立標本のSEM/CIを作りません。モデル・k・seedを自動選定しません。

## 記録と再実行

詳細は `tests/results/0.4.0a3/validation.json` とJUnit/XML、`validation/ul-subsample-0.4.0a3/` のExcel/NPZ/manifestに保存します。検証器は保存した特徴量とindexから前処理・ARI・集計を検査し、クラスタモデルの再学習やSilhouette全件の再計算はしません。

```sh
.venv/bin/python scripts/verify_ul_subsample.py --output /新規保存先/development
別wheel環境/bin/python scripts/verify_ul_subsample.py --output /新規保存先/wheel --compare /新規保存先/development
```

独立wheel環境はsystem-site-packagesを使用せず、ソースをPYTHONPATHへ追加せずに実行します。requirements-local.lock.txtの依存とビルドした0.4.0a3 wheelを導入します。

測定時間はCLIの起動から前処理・全候補学習/指標計算・反復対集計・途中保存・Excel/NPZ保存までを含み、別途行う保存結果検証器の時間は含みません。同じ実行ホストで複数の検証を行っているため、環境間の速度優劣や将来の実行時間保証には使いません。

結果は固定観測データに対する行欠落の感度です。bootstrap、未知データに対する性能保証、再標本化方式間の比較を実装・検証したものではありません。別OS/GPU/ライブラリ版でのビット一致は保証しません。
