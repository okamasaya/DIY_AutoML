# DIY AutoML 修正方針（2026-11-10）

対象：0.4.0a7の紹介記事・実験解説・DS向け記事、発表資料、および関連する評価出力。

目的は、実際の実行結果と出力を読者が確認でき、結果から言えることと次に確認することが分かる紹介へ整えること。評価条件の正確さと、分かりやすさを両立する。

本書は会話で整理した方針と作業順の記録であり、各修正の実施記録ではない。今回の変更は本書の追加のみ。記事本文・公開設定・コード・保存済み成果物の修正は後続作業として扱う。

## 1. 記事間リンクの整理を先に区切る

- 記事から別の記事を案内するリンクは、対応するZenn掲載記事を参照する。
- コード・実験手順・Excel等の成果物はGitHubを参照する。
- Zenn側のリンクは本人から修正済みとの共有あり。GitHub側の原稿は本人がWeb版で更新する予定。
- 本文の修正を始める前に、その更新を確認し、Zenn掲載版とGit原稿を照合する。Zennの記事URLは実在するURLで確認する。
- このリンク整理の完了後に、以下の反省点の修正へ進む。

## 2. 最初に、結果の解釈と結論の表現を揃える

観測した点数、差の不確かさ、採用・保留という判断を分けて書く。レビュー表の指摘も、根拠を点検してから反映する。

### 3テーマの記述の基準

以下は、保存済み予測からレビュー時に計算した補足試算。差は「モデル − 参考ルール」のtest macro F1。固定学習済みモデル・行単位・クラス件数固定のpaired percentile bootstrap、2,000反復、seed 43。現行パッケージの標準的な差の出力機能として実装済みとは記載しない。

| 題材 | 差の点推定 | 差の95%区間 | 記事で述べる結論 |
| --- | ---: | --- | --- |
| ホテル | −0.044 | −0.109〜＋0.018 | 点推定ではルールが上。今回の条件では、差の符号を明確に判断できるだけの根拠は得られていない |
| カフェ券 | ＋0.040 | ＋0.001〜＋0.078 | 行単位の仮定の下ではモデルに正の差がある。ただし下限は0に近く、回答者の依存を扱えていないため、新しい人への優位は確かめられていない |
| 通販 | ＋0.011 | −0.042〜＋0.059 | モデルの優位を確認できていない。同等性や「ルールで十分」が示されたとは扱わない |

- 「上回った／負けた」は点推定についての記述か、差の不確かさを考慮した結論かを明示する。スライド本文・発表者ノート・記事の要約も揃える。
- 差の区間が0を含むことを、同等性の証明へ読み替えない。簡単な方法を暫定採用する場合は、運用費用や説明のしやすさ等の判断理由を別に書く。
- 同等性を主張する場合は、実用上許容する差を事前に定め、それに合った評価を設計する。
- 陽性判定率の一致を、比較の必須条件にしない。対象人数の制約がある用途では同じ予算で比べる等、目的に合わせて設計し、閾値の選択は学習側で行う。
- 「首位との差が首位のfold SD以内」という基準で、「差あり／区別できない」を判定しない。CV平均・fold別値・差を示し、対応のある比較とfold間の依存を考慮する。記述上の目安と統計的な判定を分ける。
- 必要test件数は、想定する真の差・独立な評価単位・信頼水準・検出力等の仮定を伴う計画値として扱う。現在の「観測した差÷1.96」に基づく計算を、決着や十分な検出力の保証としない。学習量を増やせば差やSEも変わりうる。
- 回答者重複等の影響は「確認できた構造」「懸念」「未確認の影響」に分ける。モデルとルールの差への偏りの方向は、根拠なしに断定しない。
- seed感度を記録する。seed 42が他の30回の範囲外であることだけで異常とせず、testの良いseedを選び直さない。
- 統計的な不確かさ、学習手順の変動、数値計算の誤差、系統的な偏りを区別する。区間幅だけでデータ不足や品質不良の原因を診断しない。

完了の目安：3テーマの点数・差・読み方・条件が記事とスライドで一致し、断定の強さが根拠に合っている。

## 3. 実行結果とExcelを、紹介の中心に置く

記事の中だけで概要が分かり、興味を持った読者が実物や再実行手順へ進める構成にする。

### 記事ごとの役割

| 記事 | 主な役割 | 前に出す内容 |
| --- | --- | --- |
| 全体を紹介する記事 | 何をする道具で、何が手元に残るかを伝える | 動機、代表的な実行結果、Excel画像、短い実行例、関連するZenn記事 |
| ビジネス向け3テーマの実験記事 | 結果を読み、自分の課題に照らす | 件数・見逃し・誤判定、単純ルールとの比較、差の不確かさ、次の確認 |
| DS向け誤差評価の記事 | 計算と評価条件を確認し、再現できるようにする | 再標本化の単位、固定・変動させる条件、seed感度、数式、保存形式、検証手順 |

### 共通の見せ方

1. 身近な問いと、何の判断に使いたいかを書く。
2. 代表例の実行結果と、図付きExcelのスクリーンショットを見せる。
3. 「点数だけを見た読み方／不確かさも見た読み方／次に確認すること」を短く並べる。
4. 実際のExcelへのリンクを置き、ファイル名・最初に開くシート・見る列を案内する。
5. データの出典、加工条件、実行コマンド、対象バージョン、検証範囲へつなぐ。

- 既存の実測結果と保存済み成果物を優先して使う。新しく描画・計算する場合は、元の成果物を保持し、入力・方法・版を記録する。
- Excelの案内は、フォルダへのリンクだけで済ませず、対象ファイルを選べるようにする。
- 比較に使う指標の意味を短く説明し、Accuracyとmacro F1を混同しない。
- 結果の解釈に必要な条件は図や表の近くに残す。繰り返す数式・細かな制約は詳細記事や付録へ集約する。
- 実装済みの機能、レビュー時の補足試算、今後の予定を表示上も区別する。
- READMEも、目的・出力例・最短の実行例・入口を先に置き、開発経緯は後方または別文書へ整理する。
- 発表資料では、代表例の比較と件数を早い段階で見せ、その後に仕組みを説明する。CLI一覧・schema・版の履歴は付録への移動を検討する。

完了の目安：読者が「何ができるか」「結果をどう読むか」「実物を見るにはどこを開くか」「自分で試すには何を実行するか」を追える。画像の可読性、Excelの取得、リンク先、記載コマンドを確認する。

## 4. 必要な実装は、その後に小さく進める

説明の修正と新機能の実装を分け、既存の[ROADMAP](ROADMAP.md)・[評価設計](UNCERTAINTY_DESIGN.md)へ接続する。新機能は作業ブランチで進め、対象・出力仕様・確認方法を具体化してから着手する。

| 項目 | 方針・確認事項 |
| --- | --- |
| 2方法の差の区間 | 同じ評価単位と同じ再標本化indexで比較する機能を優先候補にする。モデルとルールの両予測、差の反復値、条件を保存する。既存の補足試算との一致を確認する |
| 受け手向けの要約 | 件数、差、読み方、未測定の項目、次の確認を先頭で読める形にする。不明・未測定を0として扱わない |
| bootstrapの共通化とCLI引数 | 共通実装へ整理し、select/tuneの引数を揃える。既存の既定値と保存結果との互換性を確認する |
| 検証のCLI | 検証本体は既にパッケージ内にあるため、それを呼ぶCLIの入口として整える。wheel導入後の操作を確認する |
| SLの学習seed感度 | 分割とモデル種別を固定し、学習seedを動かす反復を用意する。モデル選定からの変動とは分ける。全seedの予測と要約を保存する |
| データ点検・評価条件 | 既存ROADMAPの次の実装対象として維持する。評価単位、予測時点、ID・時刻列、特徴量からの除外を記録する。一意な数値列は管理用IDと断定して自動削除しない |
| 群・時間に合う評価以降 | データ点検の後、適切な分割・再標本化、学習曲線、選定からの反復、業務上の費用と閾値へ進む |

完了の目安：導入から実行・Excelの読解・保存値の確認・検証まで、説明どおりにたどれる。実装変更には、その性質に合った検証を行う。
